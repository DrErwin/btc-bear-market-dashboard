# v0.4.2：AI 语义增强与指标集合整理需求

> 状态：计划中。本文件只记录需求，不代表 v0.4.2 已经实现。

## 1. 版本目标

v0.4.1 负责中英文界面和普通语言指标含义。v0.4.2 在这个基础上继续降低解释成本，同时让 AI 更准确地使用指标维护者的人工判断，并清理重复证据：

1. 把用户对指标的判断写入 AI 解释 Prompt；
2. 删除 SIPL 指标，避免与 PSIP 重复计入。

本版本不重新寻找某一个“熊底时刻”，也不把用户的人工阈值改成机器评分规则。观察、深度压力、极端压力三档的数值、方向和人工含义仍是现有指标配置的依据。

## 2. 需求一：把用户对指标的判断写入 AI 解释 Prompt

### 2.1 产品要求

每个指标都应有一份由用户维护的“判断说明”，作为 AI 解释时的语义来源。它至少要说明：

- 这个指标在观察什么市场现象；
- 当前数值变大或变小时，通常代表压力、缓解、筑底证据，还是暂时没有明确方向；
- 它主要回应压力轴、筑底过程轴，还是只做背景/辅助证据；
- 观察、深度压力、极端压力三档分别应该怎样用普通语言解释；
- 使用时的限制，例如不能单独证明熊底、可能与哪些指标描述同一类现象。

当前 16 项基线的初始人工说明见[指标判断说明](../indicator-judgment-guide.md)。该文档是待接入运行时的内容来源，不代表 Prompt 已经读取它。

Prompt 由当前指标配置、用户判断说明、当前事实、阈值触发结果、最近三天状态和当前界面语言共同构建。用户修改判断说明后，下一次生成的 Prompt 和详细解释应自动反映新内容，不需要在 Prompt 模板里再手工复制一份规则。

### 2.2 AI 边界

用户判断说明是“解释框架”，不是新的投票器。AI 仍然负责综合不同指标和时间线，选择系统允许的压力轴/筑底轴状态并解释原因；不得因为某一个指标或固定数量的指标直接强制状态。

本需求明确禁止新增以下机制：

- 指标数量计分或“达到 N 个指标就进入某状态”；
- 预先写死的 `A+B=状态` 组合表；
- AI 修改阈值、方向、档位含义或数据新鲜度判断；
- 从指标判断推导价格、仓位、杠杆、买卖时机等交易建议。

### 2.3 验收标准

- 测试夹具替换一条用户判断说明后，实际运行时生成的 AI 输入中能看到新说明，且没有旧文案残留。
- AI 输出可以引用这条说明来解释现象，但仍只能使用系统允许的轴状态和阶段词汇，并跟随当前语言输出。
- 现有观察/深度压力/极端压力阈值的数值、方向、触发结果不变。
- AI 校验仍能拦截交易建议、超出允许状态、把缺失或过期数据当成证据等内容。
- 解释结果能追溯到指标 ID 和当前判断说明版本，方便日后核对“这句话是根据哪份人工判断生成的”。

## 3. 需求二：删除 SIPL 指标

### 3.1 产品要求

从 v0.4.2 的当前产品指标集合中删除 SIPL。SIPL 与 PSIP 使用同一类供应盈亏事实，继续同时展示会让用户以为有两份独立证据，也会让 AI 的解释重复。因此：

- 当前指标列表、分类数量、指标选择器和指标解释区不再展示 SIPL；
- SIPL 不再进入压力轴/筑底轴判断，也不再写入给 AI 的当前 Prompt；
- 供应盈亏这一类信息由保留的 PSIP 等指标承担，不能因为删除 SIPL 而改变 PSIP 的阈值和含义；
- 历史数据包、历史验收资料是否保留 SIPL 记录，按兼容性需要处理，但历史记录不能被改写成“从未存在”。

### 3.2 验收标准

- 当前 fixture 和浏览器页面的活动指标数量、分类数量及指标列表中均没有 SIPL。
- 生成的 AI 输入、详细解释和状态证据中没有 SIPL 作为当前证据。
- 删除 SIPL 后，PSIP 的数值、阈值、方向、图表和解释保持不变。
- 旧版本数据包仍能按既有历史契约读取，或在迁移时给出明确的兼容处理结果。
- 相关图表开关、配置、测试和文档引用同步清理，不留下指向当前 SIPL 的死入口。

## 4. 不在 v0.4.2 范围内

- 重新设计中英文切换、普通语言指标含义或默认说明栏的三栏内容与来源位置；这些属于 v0.4.1；
- 增加指标说明栏的悬浮、点击展开或其他补充交互；
- 重命名或重设计压力轴、筑底过程轴及其阶段词汇；
- 修改观察、深度压力、极端压力的阈值数值、方向或人工回测含义；
- 除本需求明确的 SIPL 外，不顺带新增、删除其他指标或重新研究阈值有效性；
- 将 AI 变成基于规则计分的状态机；
- 部署线上版本、接入真实模型验证或改变数据授权范围；
- 输出买卖、仓位、杠杆、价格目标或择时建议。

## 5. 实施前需要确认的细节

这些是进入实现计划时需要定下来的方案，不是对本需求的额外约束：

- 用户判断说明放在指标配置、独立 JSON，还是后台可编辑的配置中；
- 用户判断说明的版本号如何随 Prompt 和结果包保存；
- SIPL 删除后的历史包迁移策略，以及前端图表开关和测试的清理顺序。
