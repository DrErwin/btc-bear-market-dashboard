# v0.3.0 — 指标证据体系改造设计

> 状态：已完成讨论，等待用户对书面设计做最终复核。
>
> 日期：2026-07-28

## 1. 改造目标

把当前“16 项指标直接交给 AI 判断”的方式，改造成：

1. 机器先检查数据是否可用；
2. 机器把相关指标整理成独立证据维度；
3. 核心维度限制 AI 能选择的阶段；
4. AI 综合核心和辅助证据，面向普通人解释市场状态；
5. 16 项指标继续全部展示，但展示资格与判断资格分开。

产品仍然只提示熊底证据与市场阶段，不输出交易建议、概率、目标价、仓位或杠杆意见。

## 2. 已确认的产品决策

- 接受改造上线后当前阶段发生变化，不为保持旧结论而兼容错误逻辑。
- 16 项指标全部保留在公开页面。
- 过期或待验证指标可以展示，但不能参与阶段判断。
- AI 继续从五个固定市场阶段中选择一个阶段。
- 机器规则限制 AI 可选择的阶段范围。
- 核心指标决定阶段上限。
- 辅助指标不能越过核心上限，但必须充分说明当前阶段内部的压力、投降、恢复或矛盾。
- AI 正文面向普通人讲“这些证据合在一起说明什么”，不逐项复述指标定义和卡片数值。

## 3. 总体结构

```text
16 项指标事实
  → 数据质量闸门
  → 证据整理层
      → 核心维度与允许阶段
      → 强辅助、反面证据、下一阶段条件
  → AI 在允许范围内选择阶段并综合解释
  → 阶段、解释、指标、图表和日期组成同一个完整数据包
```

公开页面同时读取两类结果：

- 完整的 16 项指标，用于展示和追溯；
- 经过整理的证据简报，用于阶段判断和 AI 解释。

## 4. 指标角色与判断资格

“角色”和“当前是否可判断”是两个不同属性。

### 4.1 固定角色

| 角色 | 指标 | 作用 |
|---|---|---|
| 核心锚 | MVRV、Puell Multiple | 决定阶段上限的两个独立证据维度 |
| 核心复核 | AVIV | 复核 MVRV，不产生第二张估值票 |
| 强辅助 | RUL 四年 z-score、aSOPR、Seller Exhaustion、CVDD proximity | 描述亏损严重度、投降和底部候选证据 |
| 普通辅助 | STH-MVRV、PSIP、SIPL、RUP、Realized Cap NPC、HODLer NPC、`>=155d`、Thermocap z-score、Reserve Risk z-score | 解释供应盈亏、资本流、持有者行为、恢复和长期背景 |

### 4.2 当前判断资格

| 状态 | 含义 | 是否进入 AI 证据简报 |
|---|---|---|
| 当前可用 | 日期、来源和口径通过检查 | 是 |
| 仅供展示 | 数据过期或不满足当前判断要求 | 否 |
| 待验证 | 指标概念可用，但当前阈值尚未达到正式判断标准 | 否 |
| 缺失 | 当次运行没有可靠数据 | 否 |

初始迁移规则：

- HODLer NPC 与 `>=155d` 当前数据停在 2023-01-12，标为“仅供展示”。
- 两者恢复新鲜数据后仍是辅助指标，不恢复为核心指标。
- CVDD 继续展示为强辅助候选，但当前“距离 50%”规则标为“待验证”，在严格距离规则完成验证前不参与 AI 判断。

## 5. 数据质量闸门

### 5.1 日期规则

- MVRV 与 Puell 是阶段判断的关键锚，二者必须具有当前有效数据。
- 默认日频新鲜度上限为距分析日不超过两个自然日；每项指标可以在配置中声明更严格的上限。
- 阶段分析日期以两个关键锚的共同可用日期为准。
- 辅助指标不得把阶段日期拖回多年以前；它只在自己的指标日期满足新鲜度要求时参与解释。
- 每项指标必须把 `metric_date`、距分析日天数和不可用原因写入完整数据包。

### 5.2 失败边界

- MVRV 或 Puell 缺失、过期或无法判断时，不调用 AI，当前阶段为“数据不足”。
- AVIV 不可用时，估值维度仍可由 MVRV 判断，但不能获得 AVIV 复核，也不能进入最高阶段。
- 辅助指标不可用时不阻断阶段判断，只在页面标明状态。
- 抓取、计算或数据包组装发生程序性失败时，不发布半成品，继续展示上一份完整成功数据包。

## 6. 证据整理层

证据整理层不产生“16 项加权总分”。它输出三类结果。

### 6.1 核心维度

#### 估值维度

- 主锚：MVRV。
- `MVRV >= 1`：未进入估值压力区。
- `0.8 <= MVRV < 1`：估值压力观察。
- `MVRV < 0.8`：深度估值压力。
- AVIV 只增加“未复核、已复核、深度复核”标记，不单独提升估值维度等级。

#### 矿工压力维度

- 主锚：Puell Multiple。
- `Puell >= 1`：未进入矿工收入压力区。
- `0.5 <= Puell < 1`：矿工收入承压。
- `Puell < 0.5`：矿工收入深度承压。

### 6.2 辅助证据主题

相关指标先合并成普通人可以理解的主题，避免同一事实重复出现：

| 主题 | 主要指标 | 解释用途 |
|---|---|---|
| 供应亏损范围 | PSIP、SIPL、RUP、RUL z-score | 市场账面亏损有多广、多深 |
| 已实现亏损与投降 | aSOPR | 链上花费者是否正在亏损卖出 |
| 卖方耗竭 | Seller Exhaustion | 卖方压力是否接近耗竭 |
| 恢复与承接 | STH-MVRV、Realized Cap NPC | 短期持有者和资本流是否恢复 |
| 持有者行为 | HODLer NPC、`>=155d` | 长期持有者是否积累或发生老币活动 |
| 矿工背景 | Thermocap z-score | 矿工成本维度的补充背景 |
| 长期成本与信念 | CVDD、Reserve Risk z-score | 长期成本锚和持有信念背景 |

同一主题内的多个指标只能形成一组辅助证据，不能逐项累加。

### 6.3 证据简报

机器交给 AI 的内容包括：

- `allowed_stages`：本次允许选择的一个或两个相邻阶段；
- `core_dimensions`：估值和矿工压力的状态、复核情况与数据日期；
- `strong_auxiliary_themes`：当前最强的两到三组辅助主题；
- `contrary_or_incomplete`：相反或尚未完成的证据；
- `next_stage_conditions`：进入下一阶段仍缺少的核心条件；
- `data_quality`：被排除指标及原因。
- `metric_evidence`：每项指标的重要性、当前值、阈值、阈值结论和证据用途。

AI 不再直接面对未经整理的 16 项指标定义清单。

### 6.4 单项指标交给 AI 的字段

> 补充设计状态：已于 2026-07-28 确认，尚未实施。
>
> 这些字段只进入 AI 内部输入，不在公开页面新增展示。

每项指标只使用下面这组简化字段：

| 字段 | 含义 |
|---|---|
| `id` | 指标的固定编号 |
| `name` | 指标名称 |
| `importance` | 指标的重要性，以及它能否决定阶段 |
| `value` | 当前指标值 |
| `date` | 当前值对应的数据日期 |
| `status` | 当前可用、仅供展示、待验证或缺失，以及能否参与判断 |
| `thresholds` | 当前配置的判断阈值；每条包含规则、名称、含义和本次是否触发 |
| `threshold_summary` | 机器根据当前值和阈值生成的一句话结论 |
| `evidence_use` | AI 应怎样使用这项证据，以及不能怎样使用 |

以 aSOPR 为例：

```json
{
  "id": "asopr",
  "name": "aSOPR",
  "importance": "强辅助，只解释阶段内部压力，不能提高阶段",
  "value": 0.992329,
  "date": "2026-07-28",
  "status": "当前可用，可参与判断",
  "thresholds": [
    {
      "rule": "< 1.0",
      "name": "盈亏平衡线",
      "meaning": "低于该线表示链上花费整体处于亏损状态",
      "triggered": true
    }
  ],
  "threshold_summary": "当前已触发盈亏平衡线，说明市场出现亏损卖出压力。",
  "evidence_use": "用于解释投降或持续压力，但不能单独决定市场阶段。"
}
```

字段生成规则：

1. 阈值比较由机器完成；AI 只能读取 `triggered` 和 `threshold_summary`，不能重新计算或推翻结果。
2. 多档阈值全部列入 `thresholds`。每一档分别标记是否触发，`threshold_summary` 用一句话说明本次达到的最高有效档位。
3. 只把判断规则交给 AI；纯图表参考线不进入 `thresholds`。规则仍待验证时，由 `status` 标明，并且本次不执行判断。
4. 当前可用指标的 `triggered` 必须是 `true` 或 `false`。
5. 仅供展示或待验证指标仍可提供参考值、日期和阈值定义；缺失指标的 `value` 使用 `null`。三种状态的 `triggered` 都必须是 `null`，`threshold_summary` 必须明确说明本次未进行阈值判断。
6. `importance` 必须明确核心锚、核心复核、强辅助或辅助的判断权力，不能只给角色名称。
7. `evidence_use` 必须同时说清用途和边界，例如“用于说明阶段内部压力，不能提高阶段”。
8. AI 可以选取代表性指标解释证据关系，但不得把这些字段逐项改写成指标清单。

## 7. 阶段约束规则

机器只确定允许范围，AI 在范围内做最终综合判断。

| 两个核心维度的组合状态 | AVIV 复核 | AI 允许选择的阶段 |
|---|---|---|
| 两项都未触发 | 任意 | 尚未进入熊底观察期 |
| 仅一项进入观察，另一项未触发 | 任意 | 熊市下行期 |
| 两项都进入观察，或一项深压而另一项未触发 | 任意 | 熊市下行期 / 深度压力期 |
| 两项都触发、至少一项深压，但未同时深压 | 任意 | 深度压力期 / 筑底证据积累期 |
| 两项都深压 | 未达到 AVIV 深度复核 | 深度压力期 / 筑底证据积累期 |
| 两项都深压 | 达到 AVIV 深度复核 | 筑底证据积累期 / 熊底证据充分期 |

辅助证据不能扩大这个范围。AI 选择较高阶段时，必须说明不同辅助主题如何形成一致性；证据混杂或恢复尚未出现时，应选择范围中的较低阶段。

## 8. AI 解释设计

### 8.1 普通用户首先看到的内容

1. 固定阶段名称；
2. 一段综合解释；
3. 一句阶段内部压力说明；
4. 主要阻碍；
5. 下一阶段条件。

### 8.2 综合解释要求

- 先说证据合在一起说明什么，再提代表性指标。
- 说明至少两个证据维度之间的关系。
- 当存在强辅助证据时，必须说明当前阶段内部的压力、投降或恢复程度。
- 多个相关辅助指标合并成一个主题，不逐项报数。
- 首屏解释最多提及四个代表性指标名称。
- 首屏不复述公式，不重复卡片数值，不解释每项指标定义。
- AI 可以使用机器生成的 `threshold_summary` 理解证据，但不得逐项复述全部阈值。
- 详细指标、数值、阈值和日期放在展开后的证据依据中。

### 8.3 AI 输出结构

- `stage`：必须属于 `allowed_stages`。
- `summary`：面向普通人的综合判断。
- `pressure_summary`：存在强辅助主题时必填；没有时为空。
- `compact.support`：核心阶段依据。
- `compact.obstacle`：主要反面或未完成证据。
- `compact.next`：下一阶段条件。
- `detailed`：核心依据、辅助主题、相反证据和数据限制的完整说明。

## 9. 页面表达

- 保留 16 项指标和六个现有展示分类。
- 指标角色标签改为“核心锚、核心复核、强辅助、辅助”。
- 数据状态单独显示“当前可用、仅供展示、待验证、缺失”。
- 过期指标直接显示数据截至日期和“不参与当前判断”。
- AI 首屏继续保持紧凑，不增加大面积空白。
- `pressure_summary` 放在综合解释附近；没有强辅助证据时不占空间。
- 展开区按照“核心依据、压力补充、相反证据、下一阶段条件、数据限制”组织。

## 10. 异常与回退

- 关键锚的数据质量不合格：生成一致的“数据不足”结果，不调用 AI。
- AI 返回超出允许范围的阶段、引用未触发证据或出现禁止表达：携带明确校验原因重试一次。
- 重试仍失败：不发布当前半成品，继续展示上一份完整成功包。
- 辅助指标过期：排除该指标并继续分析，不把缺失解释成反面证据。
- 仅供展示、待验证或缺失指标的 `triggered` 使用 `null`，不能用 `false` 冒充“正式检查后未触发”。
- 所有成功发布继续绑定同一 `run_id`、分析日期、指标日期、图表和 AI 解释。

## 11. 验收原则

- 离线自动化负责验证角色、数据闸门、证据去重、阶段范围、AI 输入边界、页面展示和回退。
- 真实 AI 测试使用固定证据场景，由独立子代理检查解释是否综合、易懂、没有指标复述和越权判断。
- 真实 AI 测试结果必须保留输入、输出和审查结论，但不得记录密钥。
- 最终仍使用一个机器可执行的完整验收入口。

## 12. 本版不做

- 不新增第 17 个指标。
- 不创建 16 项加权总分或底部概率。
- 不重新优化全部指标阈值。
- 不把 Seller Exhaustion 或 CVDD 升级为第三核心。
- 不改成机器完全决定唯一阶段。
- 不重新设计整个页面视觉系统。
- 不提供交易建议。
