# v0.3.0 — 指标证据体系下阶段工作计划

> 配套设计：`specs/v0.3.0/indicator-evidence-system-design.md`
>
> 目标：在不新增指标、不改变产品边界的前提下，完成“数据质量闸门 → 证据整理层 → 阶段约束 → AI 综合解释 → 普通用户展示”的完整改造。

## 1. 完成标准

本阶段只有同时满足以下结果才算完成：

1. 16 项指标全部保留展示；
2. MVRV 与 AVIV 只形成一个估值维度；
3. Puell 形成独立矿工压力维度；
4. 过期或待验证指标不能进入当前判断；
5. 机器能生成固定的 `allowed_stages`；
6. AI 只能从 `allowed_stages` 中选阶段；
7. 强辅助主题必须进入普通人可读的压力解释；
8. AI 正文不再逐项复述指标定义和数值；
9. 数据不足、AI 失败和半包发布均有可验证的处理；
10. 一个命令完成构建、离线测试、页面检查和证据输出。

## 2. 阶段总览

| 阶段 | 业务结果 | 主要产物 |
|---|---|---|
| Phase 0 | 锁定契约和场景 | 角色表、证据简报契约、阶段矩阵、固定测试场景 |
| Phase 1 | 数据先过质量闸门 | 新鲜度、判断资格、关键锚检查 |
| Phase 2 | 建立证据整理层 | 核心维度、辅助主题、去重和允许阶段 |
| Phase 3 | 改造 AI 判断与解释 | 新输入、提示词、输出契约和语义校验 |
| Phase 4 | 更新公开页面 | 新角色、数据状态、综合解释和证据展开 |
| Phase 5 | 完整验收与真实 AI 复核 | 单一验收入口、截图、历史场景、子代理 AI 测试 |
| Phase 6 | 迁移、发布和回退验证 | 新配置版本、真实日更、Cloudflare 发布、上线记录 |

## 3. Phase 0 — 契约与测试场景

### EVI-001：锁定指标角色和判断资格

**工作**

- 建立 16 项指标的唯一角色注册表。
- 把角色与数据状态拆开。
- 初始标记 HODLer NPC、`>=155d` 为“仅供展示”。
- 初始标记 CVDD 当前 50% 规则为“待验证”。

**机器验证入口**

```powershell
python -m pytest tests/acceptance/test_evidence_contract.py -q
```

**通过标准**

- 16 个指标 ID 无缺失、无重复；
- 正好 2 个核心锚、1 个核心复核、4 个强辅助、9 个普通辅助；
- HODLer NPC、`>=155d` 和 CVDD 不进入当前 AI 判断输入；
- MVRV 与 AVIV 指向同一个估值维度。

**审查证据**

- pytest 输出；
- 导出的角色与判断资格 JSON。

### EVI-002：建立固定证据场景

**工作**

建立十个不依赖网络的场景：

1. 两个核心均未触发；
2. 仅估值进入观察；
3. 仅矿工进入观察；
4. 两个核心均进入观察；
5. 一个深压、一个观察；
6. 两个深压但 AVIV 未深度复核；
7. 两个深压且 AVIV 深度复核；
8. 核心不变但多个强辅助主题同时增强；
9. 关键锚过期；
10. 辅助指标过期。

**机器验证入口**

```powershell
python -m pytest tests/acceptance/test_evidence_fixtures.py -q
```

**通过标准**

- 每个 fixture 都能被契约读取；
- 日期、阈值状态和预期允许阶段完整；
- 强辅助场景与相反证据场景分开，不靠修改提示词临时制造。

**审查证据**

- fixture 清单；
- pytest 输出。

## 4. Phase 1 — 数据质量闸门

### EVI-003：实现新鲜度和判断资格

**工作**

- 为每项指标增加指标日期、新鲜度上限、距分析日天数和不可用原因。
- 默认日频新鲜度上限设为两个自然日，并允许逐项配置。
- 关键锚使用共同可用日期；辅助指标使用自己的日期接受或排除。
- 缺失值、过期值和零分母不能转换成未触发或数值零。

**机器验证入口**

```powershell
python -m pytest tests/acceptance/test_evidence_freshness.py -q
```

**通过标准**

- 2023-01-12 的 HODLer NPC 和 `>=155d` 自动成为“仅供展示”；
- 过期辅助指标不会拖旧整个分析日期；
- 过期关键锚产生“数据不足”且不创建 AI 请求；
- 排除原因进入数据包。

**审查证据**

- 新鲜度测试输出；
- 一份“当前可用”和一份“数据不足”数据包样例。

## 5. Phase 2 — 证据整理层

### EVI-004：生成核心维度

**工作**

- 由 MVRV 生成估值维度的“未触发、观察、深度”。
- 由 AVIV 生成估值复核标记，但不得单独提升维度。
- 由 Puell 生成矿工压力的“未触发、观察、深度”。
- 保留现有阈值状态稳定规则，不在本票中重新调参。

**机器验证入口**

```powershell
python -m pytest tests/acceptance/test_core_dimensions.py -q
```

**通过标准**

- MVRV 与 AVIV 不会产生两张估值票；
- AVIV 单独触发时不能提升估值维度；
- Puell 与估值维度彼此独立；
- 边界值按设计文档逐项通过。

**审查证据**

- 核心维度矩阵测试输出；
- fixture 对应的核心维度 JSON。

### EVI-005：生成辅助主题和去重结果

**工作**

- 把除 MVRV、AVIV、Puell 外的 13 个指标整理到供应亏损、投降、卖方耗竭、恢复、持有者行为、矿工背景和长期成本主题。
- 同一主题只输出一组综合证据。
- 从不同主题中选出最强的两到三组，不能被同族指标占满。
- 输出相反证据和下一阶段条件。

**机器验证入口**

```powershell
python -m pytest tests/acceptance/test_auxiliary_themes.py -q
```

**通过标准**

- PSIP 与 SIPL 不能形成两组证据；
- 同一主题无重复投票；
- 强辅助场景一定生成 `strong_auxiliary_themes`；
- 过期或待验证指标不进入主题结论。

**审查证据**

- 主题聚合测试输出；
- 强辅助和矛盾场景的证据简报。

### EVI-006：生成 AI 允许阶段

**工作**

- 按设计中的阶段矩阵输出一个或两个相邻阶段。
- 数据不足作为独立系统状态处理。
- 辅助主题只能帮助 AI 在范围内选择，不能扩大范围。

**机器验证入口**

```powershell
python -m pytest tests/acceptance/test_stage_guardrail.py -q
```

**通过标准**

- 十个固定场景全部得到预期 `allowed_stages`；
- 单个强辅助场景不能把阶段上限抬高；
- 两个核心深压但 AVIV 未深度复核时不能允许“熊底证据充分期”；
- 任何允许范围都只包含一个阶段或两个相邻阶段。

**审查证据**

- 阶段矩阵测试输出；
- 十个场景的阶段范围汇总表。

## 6. Phase 3 — AI 判断与普通人解释

### EVI-007：改造 AI 输入边界

**工作**

- AI 改为接收证据简报，不再接收未经整理的 16 项定义清单。
- 输入保留代表性指标引用、阈值状态和数据日期，满足可追溯需要。
- 明确传入 `allowed_stages`、强辅助主题、相反证据和下一阶段条件。

**机器验证入口**

```powershell
python -m pytest tests/acceptance/test_input_boundary.py -q
```

**通过标准**

- AI 输入中不存在仅供展示或待验证指标；
- AI 输入包含两个核心维度及其日期；
- MVRV 与 AVIV 只在一个估值维度中出现；
- 图表历史、密钥和外部新闻不进入 AI 输入。

**审查证据**

- 脱敏 AI 输入样例；
- 输入边界测试输出。

### EVI-008：改造提示词和输出契约

**工作**

- 提示词要求先综合证据关系，再提代表性指标。
- 强辅助主题存在时，必须生成 `pressure_summary`。
- 输出保留阶段依据、主要阻碍和下一阶段条件。
- 校验阶段必须属于 `allowed_stages`。
- 限制首屏指标名称数量，阻止公式、数值清单和交易建议。

**机器验证入口**

```powershell
python -m pytest tests/acceptance/test_ai_contract.py tests/acceptance/test_ai_semantic_contract.py -q
```

**通过标准**

- 越界阶段被拒绝并携带明确原因重试一次；
- 未讨论强辅助主题的输出被拒绝；
- 支持证据引用未触发或被排除指标时被拒绝；
- 禁止表达被拒绝；
- 合格输出能通过旧字段兼容迁移或同步完成前端契约升级。

**审查证据**

- 合格和被拒绝输出各一份；
- pytest 输出。

## 10. 实施顺序和边界

- 严格按 Phase 0 → 6 顺序执行。
- Phase 0–3 先解决判断正确性，再修改页面。
- 每个票必须先运行自己的机器验证，再进入下一票。
- EVI-011 是合并前唯一完整离线验收门。
- EVI-012 是上线前真实 AI 质量门，按用户要求由子代理测试。
- 不在本计划中新增指标、重调全部阈值、制作概率评分或扩大交易建议范围。
- 工作区中与本计划无关的现有修改不纳入提交。
