# v0.2.0 — BTC 熊底证据看板：下一版本需求

> 状态：`v0.2.0` 需求记录，待开发。
>
> 本文只定义下一版本要达到的用户结果与验收边界；不把当前本地 fixture、未验证的指标阈值或数据代理当作正式生产结论。

---

## 1. 版本目标

让公开看板从“可本地验收的固定数据页面”升级为“每天自动更新、数据包完整一致、可按时间查看证据变化”的公开研究工具。

本版本仍是周期证据看板，不输出买卖建议、概率、目标价、仓位或杠杆建议。

---

## 2. 需求一：完整数据包与整包回退

### 用户结果

用户每次打开网页时，看到的指标、图表和 AI 阶段解释必须来自**同一份完整数据包**。每日更新要么整包成功，要么继续展示上一份完整成功数据包，不能混用不同日期的数据。

### 必须包含的内容

现有分散的 `snapshot.json`、`series.json`、`analysis-current.json`、`analysis-fallback.json` 和状态信息，合并为一份逻辑完整的数据包。数据包至少携带：

- 当日指标快照与六类状态；
- 图表历史序列与阈值线；
- 当日 AI 分析；
- 可回退的上一份成功分析；
- `run_id`、生成时间、分析日期、实际数据日期、配置版本与输入摘要。

### 发布规则

1. 只有当数据抓取、日期一致性检查、指标计算、AI 输出校验均成功时，才发布新的完整数据包。
2. 任一关键环节失败时，不得用今天的局部数据覆盖昨天的完整包。
3. 前端只读取一个“当前完整包”入口；不得分别读取会独立更新的当前快照、当前图表和当前 AI 文件。
4. 缺失或过期的关键维度必须显示“数据不足”或上一份成功结果，不能编造 AI 结论。

### 验收标准

- 人为让 AI 或任一指标抓取失败后，网页仍显示同一 `run_id` 的上一份完整包。
- 数据包内的分析日期、数据日期、图表终点和 AI 输入摘要可追溯，并且不混日期。
- 自动化测试能拒绝缺少任一必填部分、日期不一致或 AI 输出不合规的数据包。

## 3. 需求二：图表时间轴与交互缩放

### 用户结果

用户可以在共享图表中选择查看的时间范围，并直接用鼠标操作放大、缩小或移动时间窗口。纵坐标会根据当前可见时间范围自动调整，使局部变化容易看清。

### 交互要求

- 图表下方提供时间轴，显示当前查看范围；
- 用户可以选择预设时间范围；具体预设项在开发前确定；
- 支持鼠标滚轮缩放时间范围；
- 支持鼠标拖动平移时间范围；
- 图表主线、阈值线和下方柱状图始终同步使用同一时间范围；
- 纵坐标根据当前可见数据自动适配，同时保留清晰的单位和阈值语义；
- 移动端保留等价操作，不产生横向页面溢出。

### 验收标准

- 选择较短时间范围后，图表横轴范围立即更新，纵轴不再沿用全历史范围；
- 滚轮缩放和拖动后，主图与下方柱状图的日期边界一致；
- 切换指标后，时间范围保持；用户可一键回到全量范围；
- 桌面和 390px 宽移动端均能完成范围选择与缩放操作。

## 4. 需求三：HODLer 投降卖出与 >=155d 花费价值柱状图

### 用户结果

用户在查看主图时，能同时观察两类“卖出/花费压力”的时间变化，而不是只看单一折线。

### 展示要求

在共享主图下方新增柱状图区域，使用与主图完全同步的时间轴，包含：

1. **HODLer 投降卖出尖峰（占供应 %）**；
2. **`>=155d` 花费价值占比**。

每一项都必须有独立名称、单位、来源、口径说明和数据质量提示；不得把两项合并成一个未标注含义的“卖压分数”。

### 数据边界

- 两项均以百分比展示；
- 缺失日期不得前向填充为真实观测值；
- 零分母必须标记为不可判定，而不是显示为 0%；
- “HODLer 投降卖出尖峰”的最终指标 ID、数据来源与公式需在开发前完成可实现性验证；在此之前不得用近似指标冒充原定义。

### 验收标准

- 两个柱状系列均位于主图下方，标签和单位可见；
- 改变主图时间范围后，两个柱状图同步变化；
- 鼠标悬停任意柱体时，可读取日期、数值、单位和质量状态；
- 缺失或不可判定数据以明确状态表达，不伪造连续柱体。

## 5. 需求四：数据与 AI 分析自动更新脚本

### 用户结果

每天无需人工打开电脑或手动上传文件，系统会在固定时刻尝试更新数据并生成新的 AI 分析；公开网页只展示已验证成功的结果。

### 推荐运行方式

使用 **GitHub Actions 定时任务**运行更新脚本：

```
每日定时触发
  → 拉取来源数据
  → 计算与质量检查
  → 生成受约束的 AI 输入
  → 获取并校验 AI 输出
  → 生成完整数据包
  → 提交至 GitHub
  → Cloudflare Pages 自动部署
```

这条路线不需要自建服务器或自有域名：网页可继续使用 `*.pages.dev` 地址。

### 自动脚本必须做到

- 按固定 UTC 时刻每日运行，并支持手动触发用于排错；
- 使用数据源与 AI 服务的密钥，但密钥只能保存在 GitHub Actions Secrets，不能进入前端代码、公开 JSON 或日志；
- 只在共同可用日期交集上计算，不能混合不同日期的数据；
- 先完成所有检查，再原子性地生成并发布完整数据包；
- 失败时保留上一份成功包，并记录失败时间、步骤和原因；
- AI 只能从固定阶段词汇表中选阶段并说明证据，禁止交易建议；
- 自动运行现有数据契约、AI 边界和网页验收；
- 保存可审计的运行记录，包括 `run_id`、输入数据日期、配置版本、成功/失败状态。

### 验收标准

- 手动运行一次定时任务时，可以生成一份新的完整包并触发 Cloudflare 部署；
- 模拟数据源失败、AI 失败、日期不一致和输出违规四种情况时，均不会发布半成品；
- 更新流程完成后，公开站点显示的数据包版本与运行记录一致；
- API Key 不出现在 Git 历史、构建产物、网页网络响应或日志中。

## 6. 开发前待确认项

| 待确认事项 | 原因 |
|---|---|
| HODLer 投降卖出尖峰的正式定义、数据源和可用历史范围 | 不能以近似指标替代原指标后对外宣称等价。 |
| 默认时间范围选项 | 决定图表首屏的信息密度与用户操作成本。 |
| 每日更新时间 | 应晚于所用数据源的稳定出数时间。 |
| 可保留的历史数据包数量 | 决定回退、审计和存储策略。 |
| 16 个当前 fixture 指标中哪些具备可自动更新的数据来源 | 未验证或失效指标应显示“数据不足”，而不是造数。 |

---

## 7. 本版本不包含

- 买卖时机、概率、价格预测、仓位或杠杆建议；
- 公开修改阈值或指标配置的后台；
- 用无来源的模拟值填补真实数据空缺；
- 将 API Key 暴露给浏览器。
