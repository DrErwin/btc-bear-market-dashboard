# v0.3.1 — 状态阈值与图表阈值统一（历史需求）

> 状态：历史需求，已由 v0.4.0 双轴市场状态实现承接。本文只说明阈值一致性，不再定义当前运行的 AI 阶段输出。

## 1. 目标

在 v0.3.0 证据判断体系上，修正“页面画的是一组阈值、后台状态使用另一组阈值”的问题。用户在图表中看到的参考线，必须与指标卡片状态、证据简报和阶段判断使用同一口径。

STH-MVRV 是唯一例外：它没有水平参考线，但仍有三档每天实时更新的状态阈值。

## 2. 版本关系

- v0.2.4 负责图表参考线、多曲线、曲线开关和自适应纵轴。
- v0.3.0 曾负责数据质量、指标角色、证据简报、`allowed_stages` 和 AI 阶段约束。
- v0.3.1 在两者之上统一阈值来源；v0.4.0 继续使用这些阈值事实，但替换了单一阶段契约。
- 本次复用 v0.2.4 保存的配置文件：`specs/v0.2.4/btc-indicator-config-2026-07-28.json`。
- 配置文件 SHA-256：`435BB97DF65A69F1C50E084AB3C18A048D2AED57699B1E2945BDC1B72C2AFF81`。

## 3. 非 STH-MVRV 指标

- 15 个非 STH-MVRV 指标的图表阈值与状态阈值必须在数量、数值、方向和名称上完全一致。
- 同一组阈值同时进入 `series.metrics[].thresholds` 和 `snapshot.metrics[].thresholds`。
- 指标卡片状态取当前值实际触发的最深命名档位，例如“观察区”“深度压力区”或“极端压力区”。
- v0.3.0 的证据编译器必须读取当日快照阈值，不得继续使用独立硬编码的 MVRV、Puell 或 AVIV 阈值。
- 阈值调整后，当前 v0.4.0 证据简报必须在同一次每日运行中重新计算；AI 在压力轴和筑底轴的固定词汇表内综合解释。

## 4. STH-MVRV 特例

- 图表不绘制 STH-MVRV 水平参考线，也不显示“阈值线”开关。
- 统计样本为从 `2018-01-01` 起到本次运行最新可用日期的 STH-MVRV 历史值。
- `5%分位` 对应“观察区”。
- `均值 − 1.5 × 标准差` 对应“深度压力区”。
- `中位数 − 1.5 × 1.4826 × MAD` 对应“极端压力区”。MAD 是历史值与中位数距离的中位数。
- 三档阈值每次每日运行都要重新计算，不能把某一天的结果写成永久常量。
- 三条战术价格曲线分别等于上述阈值乘以当日 STH-RP，并随每日计算结果更新。
- STH-MVRV 仍是辅助证据，不能单独提高整体阶段。

## 5. 验收要求

- 自动检查 15/15 个非 STH-MVRV 指标的图表阈值与状态阈值完全一致。
- 自动检查 STH-MVRV 的状态快照有且只有三档动态阈值，图表阈值为 0 条。
- 向历史样本加入新的当日数据后，STH-MVRV 三档阈值必须发生重新计算。
- 状态标签必须返回最深的已触发命名档位。
- 历史 v0.3.0 的 `allowed_stages` 保护不再是当前契约；v0.4.0 改为固定双轴词汇、输入边界和语义校验，关键数据不足时明确报告数据不足。
- `python -m pytest -q tests/acceptance`、`cd dashboard && npm run build` 和浏览器验收入口必须通过。

## 6. 边界

- 不新增指标，不改变固定阶段词汇表，不改变原始数据来源。
- 不把完整图表历史发送给 AI。
- 不提供交易建议、价格预测、仓位或杠杆建议。
- 本文描述的是本地 v0.3.1 功能修订；正式发布前仍需更新运行包版本标识并完成线上核验。
